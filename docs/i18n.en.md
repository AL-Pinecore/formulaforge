# Internationalization (i18n)

Purpose: Chinese/English UI switching, system-language detection, MathLive string overrides, and adding a new language with zero code changes.

## Files

- `app/composables/useI18n.ts` — i18n core
- `app/locales/en.ts` / `app/locales/zh.ts` — language packs
- `app/plugins/mathlive.client.ts` — MathLive string injection and locale sync

## How it works

### Auto-discovery of language packs

`useI18n.ts` loads every locale file with `import.meta.glob('../locales/*.ts', { eager: true })`. Each file exports `default` (with `languageCode`/`displayName` plus UI translations) and `mathlive` (MathLive string overrides). Discovery validates that `languageCode`, `displayName`, and `mathlive` are present, skipping invalid files.

`availableLocales` is derived from the dictionaries, so the language selector renders automatically — no hardcoded language list.

### `t()` resolution & fallback

`t(key, params?, fallback?)` supports dot paths (`t('category.basic')` → `dictionary.category.basic`). Missing keys fall back to `en`, then to `fallback`, then to the key itself. `{name}` placeholders are filled by `interpolate` from `params`.

### Language detection & persistence

`readStoredLocale()` reads localStorage (`formulaforge.locale`), falling back to `detectSystemLocale()` (`navigator.language` exact/prefix match), then to `en`. `setLocale` validates, writes localStorage, and updates `document.documentElement.lang`.

### MathLive strings

In `mathlive.client.ts`, `MathfieldElement.strings = mathliveStrings` (for the current locale), and a `watch(locale)` keeps `MathfieldElement.locale` in sync. This way the math field's menus/hints follow the language switch.

## Design choices

- **glob auto-discovery**: adding a language means dropping in a locale file — no component or plugin changes (the README's "Adding a New Language" section details the convention).
- **`en` as the single fallback source**: the `t()` chain guarantees an English fallback for any missing key.

## Known limits

- Interpolation only supports `{word}` named placeholders, not ICU features like plural/gender (not needed by current strings).
- Locale filenames are organizational only; `languageCode` is the actual language identity.
